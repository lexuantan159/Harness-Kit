# Brainstorming

1. **Frame the problem** - who has it, how often, what it costs today, what "solved" looks like.
   Ask at most 3 clarifying questions, one at a time, if the problem itself is unclear.
2. **Diverge** - list 3-5 genuinely different approaches, including "do nothing", "process
   change instead of code" and "use what we already have".
3. **Sketch each** in 2-3 lines: how it works, effort (S/M/L), main risk, what it rules out later.
4. **Converge** - recommend one with the trade-off you accept. Say what would change your mind.
5. **Next step** - `/assess` for a go/no-go, or `/spec` / `/plan` if already agreed.

Rules: no code during brainstorming. Ground options in the existing architecture
(`docs/ai/context/ARCHITECTURE.md`). Prefer the boring option when value is equal.
